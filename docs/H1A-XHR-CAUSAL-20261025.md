## Locally demonstrated harness defect

In `installScopedRoutes()`, each `Fetch.requestPaused` request ID receives an ordinal, while `Network` events are associated through `networkId`. With a same-origin XHR 307 redirect, real Chromium emits two Fetch request IDs sharing one Network ID and emits `Network.loadingFinished` only for the final hop. Before this change, a new real-Chromium regression failed with `XHR_INCOMPLETE`: first hop had REQUEST and RESPONSE 307 but no TERMINAL; second hop had REQUEST, RESPONSE 200, and NETWORK_FINISHED. This is a harness correlation defect, independent of the hosted ordinal 14 cancellation. The hosted 16-19 have no RESPONSE, so this particular redirect shape does not explain them either.

The fix emits a closed `REDIRECT_FOLLOWED` terminal only after the successor request, linked by the same Network ID, is allowed and continued at the pinned origin. The evaluator requires a 3xx parent response, matching parent and child ordinal links, and a terminal for the final child. Missing, forged, external, cancelled, or unfinished successors still block. No HTTP 200 alone counts as body completion. The original real-Chromium test failed before and passed after the fix.

`networkidle` is a page-load heuristic, not a CDP trace barrier. The Auth-only probe now allows a bounded three-second closure interval and requires each observed request to have a terminal plus a short quiet interval. If a terminal is still missing at the deadline, the existing `XHR_INCOMPLETE` block remains. Real Chromium tests show an active XHR fails when evaluated early, passes only after its actual response and loading completion, and still fails when no terminal arrives.

The run remained `XHR_TERMINAL_UNVERIFIED` as required. Local Auth users, organizations, projects, and outbox total/pending were zero by SQL read; the exact stack was retired with zero containers and its work directory removed. The temporary diagnostic script was removed; no raw URL, header, token, or account identifier was committed.

## Remaining causal question and discriminating experiment

This local fix removes one demonstrable false `XHR_INCOMPLETE` for redirect chains. It does not explain the hosted cancellation of ordinal 14 or the four request-only rows. Before any new hosted diagnostic run, add bounded, closed initiator and lifecycle categories: script source class (Next static bundle, pinned application bundle, other/unknown), `_rsc` presence, link-target match against the DOM of the same page, explicit prefetch hint, phase when the request began and ended, redirect-parent ordinal, and whether the observation deadline expired with a request active. Do not persist script URLs, call frames, network IDs, headers, cookies, tokens, or free CDP text. Prove those categories with Chromium locally, then request separate authorization for one protected, Auth-only probe if local evidence remains non-equivalent. Distinguishing results: a linked redirect with a completed final body can pass; a necessary request cancellation or any missing terminal must block; a candidate optional cancellation requires same-run initiator and independence evidence before any contract change. The same run must also retain POST 303, session, origin, and interception checks. Cleanup remains exact-run Auth deletion and an independent Preview read before teardown.

H1-A, R1, H1-B/U04, H1 global, and H2 keep their separate gates. U03/I-2/I-5 remain closed.

## Inventario previsto antes de navegar

El ensayo `u03-window-http-restore.integration.test.ts` creó con Auth local un propietario y un segundo usuario. Cada usuario creó su propia organización y proyecto mediante RLS. El flujo de producto `providers.runProviderRequest` → `storeProviderResult`, con anillo de firma del servidor y principal local mínimo, insertó una fila ficticia de Search Console en cada proyecto. El proyecto A también tenía auditoría firmada e import. El valor de medición esperado era una fila con la métrica «Clics»; el código de `measurementRows` muestra «Fila de datos» cuando la consulta firmada no declara dimensiones, por lo que el texto de la query no es una aserción válida sobre el HTML. La página de informe lee los resultados con la sesión y RLS.

La comparación experimental interceptó una precarga del `<Link>` de proyecto por el origen fijado. En A dejó completar la respuesta. En B llamó a `response.body.cancel()` después de HTTP 200, antes de devolverla a Next. Conservó IDs de red solo en memoria y exigió una petición no-prefetch del mismo path con RESPONSE 200 y `Network.loadingFinished` propio. No otorgó PASS a una cancelación. Los cambios temporales al test se retiraron al terminar; el diff publicado solo conserva este expediente.

El resultado A confirma que la build local sirve medición poblada y firmada. El resultado B **no demuestra** que el cuerpo de una precarga cancelada se sustituyera por una petición directa completa del mismo destino. Tampoco demuestra que no existiera sustitución: la correlación del comparador puede haber clasificado como precarga una solicitud directa o la navegación pudo usar otra ruta/cache. Antes de afirmar independencia faltan, en el mismo ensayo, una correlación estable entre el enlace, precarga y solicitud sustituta; prueba de que el cuerpo cancelado no se consumió; y comparación exacta de contenido firmado, permisos y aislamiento en las cuatro vistas. El escenario C debe mostrar que una solicitud necesaria incompleta sigue BLOCKED. Una vista visible o RESPONSE 200 no sustituyen esas pruebas.

El fallo alojado histórico del ordinal 23 permanece separado: su ledger registra RESPONSE 200 y NETWORK_CANCELLED en SESSION, pero carece de consumidor, sustituta y actor del aborto. No puede recibir retrospectivamente los campos del ensayo local.

## Decisión y siguiente experimento local

**EVIDENCIA INSUFICIENTE.** Conservar el gate actual, que bloquea cancelaciones y solicitudes sin terminal. No preparar lote, deployment ni sonda Preview. El próximo experimento local debe clasificar en memoria todas las solicitudes del path por `Next-Router-Prefetch`, tipo de navegación y redirección, y comparar el cuerpo firmado que acaba en cada vista con el resultado verificado del repositorio, en escritorio y móvil. Debe publicar solo categorías y booleanos saneados. Si no existe sustituta completa del mismo destino, la clase permanece necesaria o indeterminada. Si la prueba local pasa, aún faltaría diseñar cómo acreditar los mismos predicados en un run alojado nuevo antes de someter un cambio contractual a revisión.

## Contratos revisados

- `src/app/proyectos/[tenantId]/[projectId]/exportar/route.ts` devuelve 404 para usuario/tenant/proyecto/permiso desconocido, pero en éxito añade un evento firmado `project.export`; no es una ruta inocua para un control positivo si el escritor está bloqueado.
- La página de auditoría técnica solo lee estado/configuración; las acciones OpenSEO llaman primero `writerReady()` y salen antes de invocar proveedor si el escritor no está disponible. En Preview `readOpenSeoConfig` y `readOpenSeoMcpConfig` fuerzan el bloqueo de proveedor.
- La página de resultado carga y verifica `provider_results` por proyecto e ID; una fila positiva necesita firma real del flujo de persistencia.
- `imports` usa `uploadImport` y `importFile`; la eliminación llama `delete_import_with_receipt` y procesa el recibo. El flujo puede probarse solo si preflight acredita keyring y capacidad legítima para procesar ambos recibos sin dejar outbox pendiente.
- `src/lib/supabase/proxy.ts` hace `getClaims()` por petición y escribe cookies renovadas mediante `setAll`; el test S-2 debe esperar el vencimiento de `exp` real, no fabricar un token expirado.

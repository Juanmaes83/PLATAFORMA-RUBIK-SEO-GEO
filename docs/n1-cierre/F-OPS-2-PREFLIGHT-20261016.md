## Causa raíz y contrato

Google reservaba `google_capture`, llamaba al proveedor y solo después intentaba `completeTrustedProviderCommand`. OpenSEO reservaba un job antes de iniciar el rastreo, pero la reserva no probaba que el escritor SQL S1 pudiera conectar, firmar y completar. Las acciones de conexión ejecutaban el RPC de negocio antes de `appendAudit`. La presencia de banderas o de `RUBIK_AUDIT_DATABASE_URL` no demuestra disponibilidad.

`preflightTrustedWriter` comprueba sin escribir: conexión con el pool SQL dedicado, permisos de lectura/inserción y de outbox, funciones SQL para la operación, usuario autenticado, membresía del proyecto en el mismo SQL, alcance organización/proyecto y validez de la cadena HMAC completa. La transacción no emite mutaciones y termina en rollback; usa `BEGIN` porque la función de membresía bloquea filas con `FOR SHARE`, incompatible con `BEGIN READ ONLY`. No crea recibos ni consulta proveedores. El error estable `WRITER_UNAVAILABLE` / `AUDIT_WRITER_UNAVAILABLE` precede a la reserva y a la llamada externa. Las Server Actions devuelven código de aplicación; la captura Google redirige con `?error=WRITER_UNAVAILABLE`. No existe hoy una respuesta HTTP 503 uniforme para Server Actions.

La autorización de `manage-connectors` se conserva en las acciones OpenSEO; Google conserva la comprobación de fuente y rol del RPC. El preflight vuelve a validar actor/alcance con la identidad SQL dedicada. No usa `service_role` como escritor ni expone claves. La verificación no se almacena en caché para evitar disponibilidad ficticia. Los reintentos mantienen las claves y reservas previas; el preflight no crea una nueva operación.

Si el guardado OpenSEO confirma datos pero el recibo no se puede firmar, la respuesta y la UI ahora muestran `audit-pending` y solicitan drenaje por el operador. No indican que el resultado carece de guardado ni que su auditoría está completa. La captura Google ya mostraba explícitamente `guardada-sin-auditoria`.
